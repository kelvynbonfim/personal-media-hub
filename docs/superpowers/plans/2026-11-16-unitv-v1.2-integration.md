# UniTV v1.2.0 Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore exclusive UniTV integration targeting `https://www.unitvwebs.com`, remove AnimeFire/AnimesOnlineCC, support visible in-app WebView `/captcha`/login/search modals when needed, and render the app's own player HUD over `#v-player_html5_api` for `v1.2.0`.

**Architecture:** `RuntimeWebViewBridgeController` and `RuntimeWebViewBridgeHost` run silently by default and promote a theme-matched visible modal whenever `/captcha`, manual login, or Quasar `/search/vod` selection requires user interaction, while `UniTvPlaybackAdapter` skips legacy 8-second extraction for `unitvwebs.com` (`webViewDirectHosts`) and preserves existing extraction fallback for other portals. `VideoPlayerScreen` keeps `CLEAN_WEBVIEW` fullscreen with site chrome hidden via CSS and drives `#v-player_html5_api` bidirectionally (`WEB_PLAYER_STATE`, `WEB_PLAYER_INTERACTION_REQUIRED`, and native HUD controls).

**Tech Stack:** TypeScript, React Native (Expo ~52.0.49), `react-native-webview` (13.12.5), `react-native-video` (^6.19.3), `expo-sqlite`, `expo-secure-store`, Jest (`ts-jest` node environment).

**Spec:** [2026-11-16-unitv-v1.2-integration-design.md](file:///c:/Users/Kekel/Documents/App%20M%C3%ADdia/docs/superpowers/specs/2026-11-16-unitv-v1.2-integration-design.md)

## Global Constraints
- Preserve `package`: `com.personal.mediahub`, `versionCode`: `3`, `version`: `1.2.0` (`buildNumber: 3`) so the in-app updater upgrades `v1.1.0` without losing local SQLite data or credentials.
- Default UniTV portal URL is `https://www.unitvwebs.com`; migrate legacy `uvwebs.info` rows while preserving custom URLs.
- Remove `AnimeFire` and `AnimesOnlineCC` (`src/playback/auto-anime-adapter.ts` and `tests/playback/auto-anime-adapter.test.ts`).
- Follow `THEME_TOKENS` (`src/theme/tokens.ts`) with touch targets `>= 44 px` on every new/modified modal and HUD control.
- Never classify `/captcha` or manual user modal cancellation as `AUTH_FAILED`; use `CAPTCHA_REQUIRED` and `USER_CANCELLED`.
- Never automate/bypass `/captcha`, never show Quasar/Video.js chrome during normal playback, and never store/log passwords, cookies, or tokens.
- Keep `injectedJavaScript={CLEAN_WEBVIEW_INJECT_SCRIPT}` on `VideoPlayerScreen` WebView and preserve `testID="player-webview-complete-button"` (`'Concluir Episódio ✓'`) and existing test contracts for non-direct hosts (`uvwebs.info`, `https://cdn.unitv.example/...`).
- Keep `.github/workflows/android-apk.yml` on `main` untouched; do not merge or push to `main` until all tasks and whole-branch verification pass.

## Review Focus
1. **Sanitization / No credential leaks in errors or logs:** Whenever `CAPTCHA_REQUIRED`, `USER_CANCELLED`, or `AUTH_FAILED` occurs, neither `SettingsScreen` probe copy, `VideoPlayerScreen` error copy, nor bridge/navigation telemetry includes saved usernames, passwords, cookies, or query parameters (pinned in Task 2, Task 3, and Task 4 tests).
2. **Preserve custom portal URLs on SQLite migration:** Users already saving `https://www.unitvwebs.com` or a custom mirror in `app_settings` retain their exact URL across `initializeDatabase()`, while only `uvwebs.info` rows migrate to `https://www.unitvwebs.com` (pinned in Task 1 test).
3. **Never crash `CLEAN_WEBVIEW` by promoting `http://` cleartext streams into `ExoPlayer`:** `VideoPlayerScreen` ignores `STREAM_CAPTURED` events with `http://` URLs or coming from direct-WebView portals (`unitvwebs.com`), keeping playback stably inside `CLEAN_WEBVIEW` while preserving HTTPS promotion on non-direct portals (pinned in Task 5 test).
4. **Clean settlement when modal is cancelled or WebView unmounts mid-flight:** Aborting/cancelling the interactive modal or unmounting `RuntimeWebViewBridgeHost` mid-navigation resolves pending promises with `{ errorCode: 'USER_CANCELLED' }` cleanly, resets modal state, and leaves no dangling callbacks (pinned in Task 3 test).
5. **Safe numeric clamping for WebView telemetry & 85% progress persistence:** `WEB_PLAYER_STATE` messages with `0`, `NaN`, or negative duration/currentTime never pass `NaN` to `<video>.currentTime` or SQLite and still auto-complete episodes at `>= 85%` (pinned in Task 5 test).
